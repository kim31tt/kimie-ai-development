# KIMIE | Chat & Todo

公開URL: https://kimie-ai-development.vercel.app/

案件の送り先別チャットから始める、操作できる試作版です。話題・Todoを事前に作成する必要はありません。

## できること

- 案件を開いたら、社内・施主・取引先のチャットにそのまま投稿
- 投稿の「この話を続ける」から返信すると、名前入力なしで会話を分岐
- 同じ投稿からの続きは同じ会話に集約。元の投稿・送り先との関連を保持
- 「相手を選んで連絡」で同じ参加者のチャットを再利用し、新しい組み合わせだけグループを作成
- 投稿の「別の相手に相談」で共有する文章を作成。元の本文・タイトルは自動転送せず、社内だけ関連リンクを表示
- 未解決・返答待ち・解決済みで話題を管理し、期限超過を優先表示
- 相談中・Todo・返答待ちへ自動で仮分類。参考共有だけでは追跡項目を増やしません（外部AIなし）
- Todoの担当・期限・内容を確認し、完了／未完了を切り替え
- Todoから元の会話・メッセージへ移動
- 投稿の手動Todo化、検索、案件切り替え、送り先ごとの閲覧プレビュー
- 入力内容をlocalStorageに保存。再読み込み後も保持

## 試作版の範囲

実際の送信、アカウント、サーバー保存、通知、複数人の同期はありません。
閲覧プレビューは画面のフィルターであり、セキュリティ上のアクセス制御ではありません。
ブラウザには全サンプルデータが存在するため、本物の機密情報・個人情報は登録しないでください。
別ブラウザや端末とはデータを共有しません。ブラウザのサイトデータを削除すると内容が失われます。
担当者の明示がなければ未割当です。生成時にはフォームを開かず会話を継続できます。内容・担当・期限は後から編集でき、確認前のTodoも直接完了できます。
日付抽出は今日／明日／明後日／曜日／月日形式を扱います。複雑な依頼・否定表現は正しく判定できない場合があります。

## ローカル実行・検証

ビルド・依存パッケージ・環境変数は不要です。ES Modulesを使うためHTTPサーバー経由で開きます。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
node --test tests/model.test.mjs
```

- `index.html` : ページの入口
- `styles.css` : レスポンシブ画面
- `app.mjs` : 画面・操作・保存
- `model.mjs` : サンプルデータ・Todo生成・状態遷移
- `tests/model.test.mjs` : Todo生成、関連付け、解決条件、閲覧フィルターなどの検証

開発元 `kim31tt/kimie-ai-development` のmainへpush → Actionsが配信用 `MasaomiF/kimie-ai-development` のmainへ同期 → Vercelが自動公開します。

既存のブラウザ保存データを維持したまま、各案件のチャットを追加します。既存の話題は、同じ参加者のチャット内にある「このチャットの話題」から引き続き開けます。

## 会話からの自動フォロー

普段は参加者が固定された案件チャットに投稿します。サンプルの相手は社内・田中様・山本さんです。自社・取引先・施主・その他にメンバーを追加し、任意の組み合わせを選べます。追加はブラウザ内の全案件で共通です。同名の場合は会社名などで区別してください。既存チャットの参加者は変わりません。
「この話を続ける」で同じ相手との内容別会話を作り、「別の相手に相談」でも参加者の組み合わせで既存チャットを再利用します。既存チャットの参加者は変えません。新しい組み合わせは任意の名前でグループを作り、チャット一覧に追加します。過去の個別の話題は維持します。共有文の初期値は空で、元の投稿を明示的に下書きへコピーすることもできます。関連元の参照は社内表示のみです。

会話ごとにフォローを1件持ち、相談中・Todo・返答待ちに仮分類します。参考情報だけの会話は追跡せず、後から依頼が出た場合に登録します。元の投稿に追跡項目があれば引き継ぎます。返信で期限・参加者内の担当を補足し、相談から具体的な依頼になればTodoへ更新します。単なる相談表現で既存のTodoや返答待ちを相談中へ戻しません。「対応しました」は完了候補となり、ユーザーが確定します。

不要な項目は「フォローから外す」で解除でき、解除中は自動で復活しません。「解除済み」一覧または「追跡を再開」から戻せます。編集画面で保存した分類と、手動変更した内容・担当・期限は自動更新しません。旧データのTodoは再分類せず保持し、既存の分岐会話は次の投稿時に追跡を関連付けます。

すべてブラウザ内のルール処理で、AI API・サーバー処理は使いません。複数の用件や曖昧な発言を正しく解釈できないことがあるため、分類は修正でき、別の用件はさらに会話を分けられます。

## 案件内メッセージ検索

上部の「この案件のメッセージを検索」で、選択中の案件のチャット・グループ・個別の会話・解決済みの投稿を検索できます。
複数キーワードに対応し、全角英数と大文字小文字の違いを吸収します。結果の件数に上限はありません。
結果には送り先・投稿者・日時・本文を表示し、選ぶと元の投稿へ移動してハイライトします。
別案件と、閲覧プレビューの参加者外の投稿は検索対象外です。

## 話題の表示

左側は相手・グループの一覧だけを表示します。話題別のやり取りは同じ参加者のチャット内で開き、相手の選択表示を維持します。
投稿の「この話題を開く」または「このチャットの話題」から移動できます。解決済みや元投稿のない旧データも残ります。
話題の画面には親チャットへ戻るボタンを設け、Todo・フォローと案件内検索からも同じ画面へ移動できます。

## Todoの詳細管理

表形式で着手予定日・期限・複数担当者・待ち原因を表示します。タスク名から編集し、任意で優先度とメモ、小タスクを追加できます。小タスクにも着手予定日・期限・複数担当者を設定でき、一覧で展開できます。担当者は会話の参加者から選びます。未完了の小タスクがあれば親を完了できず、小タスクを再開すると親も再開します。期限や予定は自動では連動しません。従来の保存データも保持します。

## アプリ一覧とURL

トップ `/` はKIMIE AI Developmentのアプリ一覧です。Chat & Todoは `/chat-todo/` に配置し、アプリ内の「アプリ一覧」またはKIMIEロゴからトップに戻れます。既存の保存キーとドメインは維持するため、このURL変更によるブラウザ保存データの移行は不要です。

アプリの追加時は専用ディレクトリを作成し、`apps.mjs` の一覧に名前・説明・URL・タグを登録します。入口は同じタブで開きます。トップページはログイン権限を付与せず、各アプリ側で権限を検証します。

## 業務記録（ログイン不要の試作版）

トップの「業務記録」から `/work-records/` を開いて利用できます。日付・業務名・内容・作業時間の登録、編集、削除、月別表示、検索、合計時間、JSON書き出しに対応します。Supabaseやログインの設定は不要です。

記録はこの端末・ブラウザのlocalStorageに保存されます。別端末や別ブラウザとの同期はありません。同じブラウザを使用する人は記録を閲覧できます。ブラウザのデータ削除で消えるため、必要な記録は「記録を書き出す」で保存してください。Chat & Todoの保存領域とは独立しています。

`node --test tests/*.test.mjs` で既存モデルと業務記録の保存・入力検証・競合・保存失敗を確認できます。複数ユーザー版は `feat/multi-user-platform` で開発を継続し、本番のChat & Todoは変更しません。
